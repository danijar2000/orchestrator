# llm-orchestrator: контекст проекта

Личный оркестратор долгих задач для локальных LLM (Ollama). Пользователь один, авторизации нет. Код минимальный, без подробных комментариев.

**Как работает:** на сайте ставится главная задача. Агент на Mac забирает её, модель-планировщик разбивает её на шаги с критериями готовности. Каждый шаг выполняет исполнитель, затем модель-проверяющий ставит оценку 0–10 (≥7 — принято). На шаг до 3 попыток, после неудачи следующая попытка получает отзыв проверяющего. Итоговая проверка может добавить недостающие шаги. Пока идёт работа, Mac не засыпает (`caffeinate`).

**Стек:**
- `cmd/server`: Go, `net/http`, SQLite (`modernc.org/sqlite`), SSE, фронт встроен через `embed`.
- `cmd/agent`: Go, Ollama `/api/chat` с JSON schema. Состояние задач хранится локально в `~/.llm-orchestrator/`, события отправляются на сервер пачками.
- `internal/model`: общие структуры Task/Step/Attempt/Review/Event/Command.
- `web/`: React 19, Vite, TypeScript, Tailwind 4, TanStack Query и Table v8, dnd-kit, ECharts. Тёмная тема, интерфейс на русском.

**Исполнители шага:**
- `-harness builtin`: свой цикл инструментов в `tools.go` (list/read/write/edit/delete/run/done в JSON). Исходные файлы проекта защищены по снимку, сделанному при первом запуске, менять можно `*_test.go` и свои файлы. Есть защита от повторов и от одной и той же ошибки 3 раза подряд, имя Go-пакета подставляется автоматически, рассуждения `</think>` вырезаются.
- `-harness claude`: шаг выполняет `claude -p` (Claude Code) поверх Ollama с ограниченным `--allowedTools`. `bypassPermissions` не используется.
- `-check "go test ./..."`: агент сам запускает проверку после попытки, и её реальный вывод видит проверяющий. Если команда упала, шаг не засчитывается.

**Модели (Mac mini, 16 ГБ):** лучше всего работает `huihui_ai/qwen3-abliterated:14b-v2` (без цензуры), для харнеса — вариант `qwen3-abl-14b-16k` с `num_ctx 16384`. Модели на 30B не помещаются в память и уходят в своп (~0.7 ток/с). Рассматривались облака: ArliAI (фиксированная цена, Qwen3.8-27B-Derestricted), Featherless, аренда GPU на RunPod. Для них нужно добавить OpenAI-совместимый клиент.

**Запуск:**
```bash
make build && ./bin/server        # http://localhost:8080
./bin/agent -workdir <папка> -harness claude -check "go test ./..." \
  -planner M -worker M -reviewer M -ctx 16384 -think
```

**Известные проблемы и идеи:**
- Агент с моделями 14B медленно справляется с кодом: циклы, ложные отчёты.
- Песочница для тестов: `../llm-orchestrator-sandbox` (копия кода, в ней агент пишет тесты для сервера).
- Следующие шаги: прогнать `-harness claude` от начала до конца, добавить провайдера OpenAI-API (ArliAI/RunPod), OpenCode CLI как ещё один харнес.
