# llm-orchestrator

Агент на Mac берёт главную задачу, планирует шаги, выполняет и проверяет их локальными моделями Ollama, а прогресс отправляет на веб-сервер.

## Запуск

```bash
make build
./bin/server            # сайт: http://localhost:8080
./bin/agent             # в другом терминале
```

Задачи создаются на сайте. Результаты шагов: `output/<id задачи>/`.

## Настройки агента

```bash
./bin/agent -server http://localhost:8080 \
  -planner qwen3.5-abliterated-32k -worker dolphin3:8b -reviewer qwen3.5-abliterated-32k \
  -ctx 16384 -tries 3 -rounds 2 -awake=true -think=false
```

- `-awake` — пока идёт задача, Mac не засыпает (`caffeinate`), экран может гаснуть.
- `-think` — модель рассуждает перед ответом: медленнее, но меньше ошибок.
- `-workdir` — папка, где модель может читать и писать файлы и запускать команды.
- `-harness claude` — шаги выполняет Claude Code (`claude -p`) поверх локальной модели из `-worker`, вместо встроенного исполнителя. Разрешённые инструменты: `-harness-tools`; `-harness-local=false` — использовать API Anthropic вместо Ollama. Для Ollama нужен вариант модели с большим контекстом (например `qwen3-abl-14b-16k`).
- `-check "go test ./..."` — команда, которую агент сам запускает после каждой попытки; её реальный вывод видит проверяющий, и при ошибке шаг не засчитывается.
- `-tries` — попыток на шаг, `-rounds` — сколько раз итоговая проверка может добавить недостающие шаги.

## Разработка фронта

```bash
cd web && npm run dev   # http://localhost:5173, /api проксируется на :8080
```

## Профили (модели и провайдеры)

Агент берёт модели из `profiles.json` (пример — `profiles.example.json`; файл в git не попадает). Профиль задаёт для планировщика, исполнителя и проверяющего OpenAI-совместимый адрес (`url` до `/chat/completions`), модель, имя переменной с ключом (`key_env`) и цену в $ за 1M входных/выходных токенов (`in`/`out`). Подходит Ollama (`/v1`), vLLM на RunPod, OpenRouter и другие. Профиль выбирается на сайте при создании задачи; первый в списке — по умолчанию. Если файла нет, профиль `local` собирается из флагов `-ollama -planner -worker -reviewer`.

- `json: "object"` — для провайдеров без `json_schema` (переключается и само после ошибки 400).
- `extra` — добавляется в запрос как есть (`reasoning_effort`, `temperature`, `provider` у OpenRouter…).
- `harness: "claude"` + `harness_url` — Claude Code поверх адреса в формате Anthropic (у Ollama — корень без `/v1`).

В задаче и в каждой попытке сохраняются входные и выходные токены и стоимость (попытка — вместе с проверкой). OpenRouter отдаёт реальную цену в `usage.cost`, она важнее цены из профиля.
